A script counts. Your agent judges.

Numbers have to be reproducible, so the model never estimates one. What the model adds is judgment: telling real friction from ordinary work and writing the fix.

Run it on the strongest reasoning model you have.

  1. 1

    Read

    local script

    Parses the session transcripts your agent already saves on your machine. Nothing to log, nothing to set up.

  2. 2

    Map

    local script

    Inventories the harness: the instructions file, skills, subagents, commands, hooks, MCP servers and plugins.

  3. 3

    Suggest

    your agent

    Groups signals by cause, separates real friction from ordinary work, classifies each finding and writes the change. The script supplies every number.

  4. 4

    Compare

    local script

    After you accept a change, later runs compare that piece before and after, in errors, corrections, time and cost.

Each finding gets a class. The class picks the fix.

Rule exists, but is ignoredThe instruction is there. The agent doesn't follow it.Enforce it with a script, hook or check.

Missing instructionNothing in the harness covers it.Add it where it belongs.
Structure changeA pattern repeats across sessions.Turn it into a skill, subagent or script, or remove an unused piece.

More text is rarely the fix.

When a rule is already written and the agent ignores it, the answer is a hook or a check, not a longer prompt. The skill tells those cases apart.

Problems in a piece you don't control become recommendations. Findings already suggested, rejected or changed are listed, never repeated.

Costs come with their limits.

Time, tokens and money are counted by a local script. The numbers are why you can trust a finding, so each one says what it is.

  • Each number says what kind it is.At least, at most or about: a lower bound, an upper bound or an estimate. Numbers of different kinds are never added together.
  • Each number says how often."11 times in 6 of 41 sessions", so one bad session doesn't pass for a habit.
  • They measure what was spent, not what you'll save.A saving is claimed only after a before and after comparison shows it.
  • Your agent's own figure sits beside the estimate.Claude Code records its cost per session. The report shows both and never sums them.
  • Thin evidence is marked partial.With the reason, instead of being rounded up into a finding.

Your sessions never leave your machine.

Read in place

Transcripts are read where they are, never copied, never sent. Only derived, redacted findings are stored, in .harness-ledger/ in your project.

Secrets stay out

Every string that can reach a report goes through redaction. Hooks and MCP servers are kept as names and shapes, never their commands, arguments or env values.

No telemetry

When the script meets something it can't map, the report offers a link to a prefilled GitHub issue holding only names and counts. You read it and decide whether to send it.

Your retention, untouched

Claude Code deletes transcripts older than 30 days by default; Codex and Cursor keep theirs. The skill tells you how much history you have and never changes that setting.

Questions

Does it change my harness?

Only if you ask it to, one suggestion at a time, with confirmation, and only in harness files: instructions, skills, subagents, commands, hooks and settings. Pieces from plugins or managed settings are never edited. Findings about them become recommendations.

How much history does it need?

It works from the first run, on whatever sessions you have. Patterns across sessions need a few sessions to show up, and before and after comparisons need a minimum on each side. Below that, the report says the evidence is partial instead of guessing.

How accurate are the costs?

They are estimates with a stated method. Time excludes idle gaps, tokens come from the transcripts, and money comes from a price table you can override in .harness-ledger/config.json. Each signal says whether its number is a lower bound, an upper bound or an estimate.

A finding looks wrong for my project. What do I do?

Reject it and it won't come back. If the rule behind it seems off, ask for a rule question: the script builds a prefilled issue with the signal and your own words, and nothing from your sessions.
